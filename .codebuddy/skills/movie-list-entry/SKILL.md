# 影片片单条目解析

## 用途

把用户给的「豆瓣链接 / 豆瓣 id / 片名」解析为片单条目所需的准确字段，并按规范撰写推荐语：

- `id`：豆瓣影片主键（详情页地址由它拼接，另行存储链接属于冗余）
- `title`：片名
- `year`：上映年份（**以豆瓣口径为准**，可能与院线公映年不同，如《百鸟朝凤》豆瓣为 2013、院线公映为 2016）
- `rating`：豆瓣评分（统一保留一位小数）
- `genres`：类型标签，多类型以「 / 」分隔
- `digest`：推荐语（50~62 字，见「后处理规则」）

## 使用方法

运行内置脚本（零依赖，Node 18+）：

```bash
node <skill目录>/scripts/fetch-movie-info.mjs <链接|id|片名> [更多参数...]
```

用户同时给出链接与片名时**两者一并传入**，脚本会做交叉校验，输出中的 `crossCheck.matched` 必须为 `true`；为 `false` 时先向用户确认片名或 id 是否有误，**不得硬写**：

```bash
node scripts/fetch-movie-info.mjs "https://movie.douban.com/subject/1292052/" "肖申克的救赎"
```

只给片名时同样可用：内部走联想接口取候选，**优先取片名完全一致的候选**（接口按前缀匹配，短片名会被同名新片顶掉，如「功夫」被「功夫女足(2026)」顶到第一位），无完全一致时取第一条并给出 `titleMatchedExactly: false`——该字段为 false 时需人工确认候选，不要直接采信。单条解析结果示例：

```json
{
  "id": "1292052",
  "title": "肖申克的救赎",
  "year": "1994",
  "rating": "9.7",
  "genres": ["剧情", "犯罪"],
  "extraGenres": [],
  "subtitle": "1994 / 美国 / 剧情 犯罪 / 弗兰克·德拉邦特 / 蒂姆·罗宾斯 摩根·弗里曼",
  "doubanUrl": "https://movie.douban.com/subject/1292052"
}
```

## 数据获取通道（已实测，勿绕路）

- **可用**：联想接口 `movie.douban.com/j/subject_suggest?q=片名`（桌面 UA + `Referer: https://movie.douban.com/`），用于反查 id
- **可用**：`m.douban.com/rexxar/api/v2/movie/{id}`（iPhone UA + `Referer: https://m.douban.com/movie/subject/{id}/`），用于取年份、评分、类型、导演与主演
- **不可用**：`movie.douban.com/subject/{id}` 详情页直接抓取（curl 返 302、node fetch 拿到只有 `<title>豆瓣</title>` 的反爬占位页）——不要试图从详情页取分

## 后处理规则（必须执行）

1. **评分归一化**：接口可能返回「9」这类无小数写法，统一补成一位小数（`9.0`），与既有条目排版一致。
2. **类型合并**：以接口 `genres` 为权威列表，再看 `card_subtitle` 第 3 段是否有补充标签（传记/歌舞/西部等），有则追加；追加了哪些要在汇报里说明。
3. **推荐语（digest）由会话内撰写**，脚本不写文案。撰写要求（**短评体，用户 2026-10-11 指定的风格**）：
   - **以「【推荐理由】」开头**（页面会把「【…】」单独渲染成强调标签），后接正文
   - **80~115 字**（上限的来由：移动端正文 13px、可用宽度约 390px，超过约 115 字会排到第 5 行、页面明显滚动；推荐理由为整行铺开，不再受窄列限制）
   - 内容要**放硬货**：导演/主创、影像风格、改编来源、删减与结局争议、影史地位或社会议题，写出「为什么值得看」；不要只写题材标签（反面例子：「一部热气腾腾的本土喜剧」）
   - **不确定的事实宁可不写**：不得编造剧情、花絮、奖项与票房数字；只把握得住的信息才落笔，拿不准就退到观感层面
   - 简体中文；引用名句用「」或“”，避免与 JS 单引号冲突
   - 范式示例（盲山）：

     > 【推荐理由】李杨以近乎纪录片的冷峻，呈现女大学生被拐山村的绝望求生。因「抹黑农村」遭删减，两个结局（公安解救／村民围殴）的争议，暴露出社会对「恶的系统性」的回避。
4. **写入位置**：`src/database/movies.ts` 的 `records` 数组**末尾追加**，不重排既有条目；每条写成多行对象，字段顺序固定 `id → title → year → rating → genres → digest`：

```ts
  {
    id: '1292052',
    title: '肖申克的救赎',
    year: '1994',
    rating: '9.7',
    genres: '剧情 / 犯罪',
    digest: '一个人用二十年凿出一条通往自由的路。……',
  },
```

## 硬性约束

- **片单是个人口味，不设评分门槛**：用户指定的影片（含 6 分档）一律照录，不得用评分筛掉、替换或劝删；只在用户主动询问时才提分数高低。
- **推荐语里不要提分数、不要自贬**（如「片单里评分最低」「分不高但」）：分低不等于不好看，这类表述被用户明确纠正过；低分片同样按看点写推荐理由。
- 不得编造 id、年份、评分、类型；脚本报错先重试一次，仍失败则如实报告并请用户提供准确信息。
- 不擅自改动用户给的 `title`（超过 6 字需提炼时，先说明再改）。
- **环境纪律**：需要看页面时先 `netstat -ano | grep :6969` 判断本地 dev 是否已在运行——**在跑就复用，不重启、不再起第二个，绝不 kill 任何进程**。

## 交付自检（必须执行，任一不达标先修正再输出）

1. 同时给了链接与片名时，`crossCheck.matched` 为 `true`；
2. `rating` 为一位小数，`year` 与豆瓣口径一致；
3. `digest` 为简体中文、以「【推荐理由】」开头、字数在 **80~115** 之间，输出前报告实际字数；
4. 条目已追加到 `records` 末尾，字段顺序正确，未改动其他条目；
5. 跑过一次 `npx vue-tsc -b` 且无报错；
6. 汇报时列明：片名/id 核对结果、评分与类型的来源（接口取值 / 补充标签）、推荐语为自拟可改。
